# 리서치 문서 → 노션 정리

대상: $ARGUMENTS

아래 순서대로 진행한다. 중간에 임의로 단계를 건너뛰지 않는다.

---

## 0. 설정값

```
워크스페이스: <워크스페이스명> (<이메일>)

아카이브 DB (모든 항목, Type으로 구분): <ARCHIVE_DB_URL>
  data_source_id: <ARCHIVE_DS_ID>

도구·레시피 DB (설치해 쓰는 것만): <TOOLS_DB_URL>
  data_source_id: <TOOLS_DS_ID>

※ 실제 값은 gitignore된 .claude/notion-config.local.md 에 있음 (레포 미커밋). 실행 전 그 파일에서 읽어 채운다.
```

- 행 생성은 `notion-create-pages` + `parent: {"data_source_id": "..."}` 로 한다.
- 시작 전에 `notion-fetch`로 위 data_source를 열어 현재 속성·태그 옵션을 확인한다.
- 없는 태그를 써야 하면 `notion-update-data-source`로 옵션을 먼저 추가한 뒤 행을 만든다 (multi-select는 사전 등록 필요).
- 관계 연결: 도구 행의 `출처 문서`에 방금 만든 아카이브 페이지를 넣으면 아카이브의 `관련 도구`는 자동으로 채워진다 (양방향).
- ⚠️ `/mcp` Notion이 위 워크스페이스에 붙어 있어야 한다. 다른 워크스페이스면 위 ID가 404 → 재인증 후 진행. DB ID가 비어 있거나 접근 불가면 멈추고 사용자에게 물어본다. 임의로 새 DB를 만들지 않는다.

---

## 1. 읽기

대상 파일을 끝까지 읽는다. 일부만 읽고 판단하지 않는다.
파일이 아니라 붙여넣은 텍스트면 그대로 쓴다.

---

## 2. 중복 확인 (건너뛰지 말 것)

아카이브 DB에서 비슷한 제목·주제의 페이지를 먼저 검색한다.

- 있으면 → 새로 만들지 말고 **기존 페이지를 갱신**한다. 리서치 날짜를 새 날짜로 바꾸고, 달라진 부분만 수정하고, 본문 맨 아래에 `## 변경 이력`에 한 줄 남긴다.
- 없으면 → 3번으로 간다.

계속 쌓아가는 DB라서 중복이 제일 큰 적이다. 이 단계를 절대 생략하지 않는다.

---

## 3. 속성 채우기

### 아카이브 DB

| 속성 | 채우는 법 |
|---|---|
| 제목 | `[분야] 핵심 내용` 형식. 40자 이내. 예: `[한국어] 클로드코드 번역투 제거 스킬 총정리` |
| Type | `스킬` / `레포` / `프롬프트` / `노트` 중 하나. 리서치·개념 문서는 `노트` |
| 상태 | `발견` (새로 넣는 것 기본값) |
| 태그 | 2~4개. 기존 태그 우선 재사용 (claude/cli/korean/notion/workflow…). 원래 문서의 분류(도구·워크플로 등)도 태그로 흡수 |
| 리서치 날짜 | **문서 본문에서 찾는다.** 제목의 연도, "리서치 시점 기준", 언급된 최신 커밋·릴리스 날짜 등. 아무 데도 없을 때만 오늘 날짜 + 본문 상단에 `(날짜 추정)` 표시 |
| 부패속도 | 판단 기준 아래 참고 (신선도는 수식이라 자동) |
| 링크 | 원본 URL. 없으면 비워둔다. **절대 지어내지 않는다** |
| 모델 | 프롬프트면 모델명, 아니면 비움 |
| 관련 도구 | 이 문서에서 나온 도구 행(아래 도구·레시피)과 연결 |

**부패속도 판단 기준**
- `빠름` — 근거가 GitHub 스타 수, 버전 번호, 가격, 모델 성능 비교, "현재 최신" 류
- `보통` — 도구 사용법, 워크플로, 설정 방법
- `안썩음` — 언어학·이론·규범, 논문, 고전 텍스트

한 문서에 여러 개가 섞여 있으면 **제일 빠른 쪽**으로 잡는다.

### 도구·레시피 DB

문서에 "설치해서 쓰는 것"이 나오면 **하나씩 별도 행으로** 만든다. 여러 개를 한 행에 몰아넣지 않는다.

- 이름: 레포명 그대로 (`snflkd/fluent-korean`)
- 뭐하는 건지: 한 줄
- 설치 명령어: **원문에서 글자 그대로 복사**. 한 글자도 바꾸지 않는다
- 종류 / 링크 / 마지막 확인(리서치 날짜와 동일) / 상태 = `후보`
- 출처 문서: 방금 만든 아카이브 페이지와 연결

## 4. 본문 쓰기 — 5블록 고정

이 순서와 개수를 바꾸지 않는다.

```
## 1. 용도
왜 이게 필요한지 2~3줄. 배경 설명 늘어놓지 않는다.

## 2. 바로 실행
복붙 가능한 코드블록. 설명은 코드 한 줄당 한 줄 이하.
단계가 있으면 번호만 붙인다.

## 3. 선택 기준
선택지가 여러 개일 때 "언제 뭘 쓰나". 표로.
선택지가 하나뿐이면 이 블록은 통째로 뺀다.

## 4. 함정
한계, 주의사항, 오탐 사례, 하면 안 되는 것.
원문 Caveats가 있으면 여기에 압축해서 넣는다.

## 5. ▶ 원문 전체
노션 토글 블록. 원문을 **한 글자도 빼지 말고** 그대로 넣는다.
```

---

## 5. 압축 규칙

**줄이는 것**
- 1~4번 블록 합쳐서 원문의 25% 이내
- 중복 설명, 수식어, "~할 수 있다" 류 완곡 표현
- 배경·역사 서술 (원문 토글에 남아 있으니 괜찮다)

**절대 안 건드리는 것 (verbatim)**
- 설치 명령어, 코드 블록, 파일 경로
- 버전 번호, 날짜, 스타 수, 수치
- URL
- 논문·저자·출처 이름

수치를 요약하다가 틀리느니 아예 빼는 게 낫다. 확실하지 않으면 원문 토글에만 남긴다.

---

## 6. 보고

끝나면 아래만 출력한다. 장황하게 설명하지 않는다.

```
✅ [페이지 제목]
   리서치 날짜: YYYY-MM-DD (부패속도: X) → 신선도 🟢/🟡/🔴
   도구 N개 등록: A, B, C
   ⚠️ 판단 애매했던 것: (있으면)
```

마지막 줄이 중요하다. 날짜를 추정했거나, 도구인지 아닌지 애매했거나, 원문이 스스로 모순되는 부분이 있었으면 반드시 여기에 적는다. 조용히 넘어가지 않는다.

---

## 7. 문체

정리한 본문은 한국어로 쓴다. 번역투를 쓰지 않는다.

- "~를 통해 / ~에 대해 / ~에 있어서" 안 씀
- 이중 피동("되어진다") 안 씀
- "결론적으로", "주목할 만하다", "시사하는 바가 크다" 안 씀
- 형식명사("것", "점", "수", "바") 남발 안 함
- 문장 길이에 변화를 준다
