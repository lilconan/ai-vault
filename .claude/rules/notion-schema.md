# 노션 DB 스키마 (아카이브 + 도구·레시피)

> 실제 DB ID·URL·워크스페이스는 `.claude/notion-ids.md` 참고 (gitignore).
> 구조: "AI 아카이브" 페이지 밑 **아카이브 DB**(모든 항목, Type 구분) + **도구·레시피 DB**(설치물).
> **재사용 원칙**: ID가 살아있으면 새 DB/페이지 만들지 말고 기존 DB에 append. 못 찾으면 `notion-search`로 "AI 아카이브" 먼저 검색, 그래도 없을 때만 재생성 후 `notion-ids.md` 갱신.

## ① 아카이브 DB — 모든 항목, Type으로 구분
| 속성 | 타입 | 값 |
|------|------|-----|
| 제목 | Title | 항목 이름 |
| Type | Select | `스킬` `레포` `프롬프트` `노트` |
| 상태 | Select | `발견` `보는중` `테스트함` `실전투입` `참고용` |
| 태그 | Multi-select | claude / cli / mcp / korean / notion / workflow … (자유 추가) |
| 링크 | URL | 원본/출처 (내장·자작이면 비움) |
| 모델 | Text | 프롬프트용 모델명 (없으면 비움) |
| 리서치 날짜 | Date | 원문에서 추출 (리서치/도구 문서용, 없으면 비움) |
| 부패속도 | Select | `빠름` `보통` `안썩음` |
| 신선도 | Formula | 🟢/🟡/🔴/❓ (리서치 날짜+부패속도 자동) |
| 관련 도구 | Relation | → 도구·레시피 DB (양방향) |
| 추가일 | Created time | 자동 |

## ② 도구·레시피 DB — 설치해서 쓰는 것만 (문서에 도구 여러 개면 행 분리)
| 속성 | 타입 | 값 |
|------|------|-----|
| 이름 | Title | 레포명 그대로 |
| 뭐하는 건지 | Text | 한 줄 |
| 설치 명령어 | Text | 원문 verbatim (한 글자도 안 바꿈) |
| 종류 | Select | `플러그인` `스킬` `output-style` `CLAUDE.md 규칙` `MCP` |
| 상태 | Select | `후보` `설치함` `뺐음` |
| 링크 | URL | 레포 주소 |
| 마지막 확인 | Date | 스타수·버전 확인일 |
| 출처 문서 | Relation | → 아카이브 DB (양방향) |

## 신선도 수식 (아카이브 DB · 노션에 그대로 붙여넣기)
```
if(empty(prop("리서치 날짜")), "❓ 날짜없음",
  if(dateBetween(now(), prop("리서치 날짜"), "days") > if(prop("부패속도") == "빠름", 90, if(prop("부패속도") == "보통", 365, 3650)),
    "🔴 재확인 필요",
    if(dateBetween(now(), prop("리서치 날짜"), "days") > if(prop("부패속도") == "빠름", 45, if(prop("부패속도") == "보통", 180, 1825)),
      "🟡 슬슬 오래됨", "🟢 신선")))
```
- 부패속도 기준: `빠름`(스타수·버전·가격·모델비교·"최신" 류 → 45/90일) · `보통`(사용법·워크플로·설정 → 180/365일) · `안썩음`(이론·규범·논문·고전 → 5년/10년). 한 문서에 섞이면 제일 빠른 쪽.

## 항목 생성 방법
- `notion-create-pages` + `parent: {"data_source_id": "<아카이브 DS ID>"}`.
- properties 예: `{"제목":"...", "Type":"레포", "상태":"발견", "태그":["claude","cli"], "링크":"https://..."}` (없는 키는 생략).
- 없는 태그를 쓰려면 `notion-update-data-source`로 옵션 먼저 추가(multi-select 사전 등록 필요).
- 관계: 도구 행의 `출처 문서`에 아카이브 페이지를 넣으면 아카이브의 `관련 도구`가 자동으로 채워진다(양방향).
